# 室内照片自动建图系统：修订计划 v2

修订日期：2026-10-05。本文整合原计划、用户本轮修正及所提供的 OpenCV 标定脚本，作为第一版实施依据。本次交付为计划归档，尚未执行标定或建图，也未修改原脚本。

## 一、目标与范围

在当前 Mac 上运行本机网页，上传一组手机拍摄的室内照片，自动完成检查、特征匹配、相机定位、三角化和优化，展示可交互的三维地图。

第一版采用单目、离线、增量式 SfM。输出带颜色的稀疏点云、相机位姿、拍摄顺序及诊断报告；先输出相对尺度，允许用户选择已重建的两个对应位置并输入真实距离，将该独立模型转换为米制尺度。

第一版不包含实时视频跟踪、连续 IMU 融合、导航、完整墙面、稠密重建或纹理网格。照片 GPS、罗盘及未经验证的 MakerNote 不作为几何硬约束。

流程：拍摄标定板并生成标定档案 → 使用同一成像设置拍摄室内照片 → 上传、排序与编号 → 色彩规范化和检查 → 去畸变与相机参数接入 → SIFT → 全配对匹配与几何验证 → 增量重建和 BA → 分模型展示 → 可选真实尺寸校准 → 导出。

原计划中的 12 个算法步骤编号保留。实际采集时，第 2 步的标定必须在室内拍摄前完成；第 4 步的顺序整理在上传阶段执行。

| 子系统 | 方案 |
|---|---|
| 前端 | React、TypeScript、Vite |
| 三维查看器 | Three.js |
| 后端 | Python、FastAPI |
| 图像处理 | OpenCV、Pillow、支持色彩管理的 HEIC 解码器 |
| 标定 | 用户提供的 calibrate_camera.py |
| 建图 | 固定版本 COLMAP，CPU SIFT、匹配、增量 mapper |
| 数据 | SQLite、本地文件存储、不可覆盖的结果版本 |
| 任务 | 独立 Worker，单任务执行，其余排队 |

## 二、输入与采集约定

### 室内照片

- 每项目 10–200 张 JPEG、PNG 或 HEIC；每张不超过 30 MB，总计不超过 2 GB。
- 默认用户上传清晰照片，清晰度不是逐张人工审批环节；系统仍保留质量检查和风险反馈，不能把默认假设写成已验证事实。
- 使用与标定一致的物理镜头、倍率、分辨率、拍摄方向、对焦策略及成像模式。仅有“都是 1×”不足以证明内参一致。
- 第一版推荐整组保持同一横竖方向，避免旋转后的切向畸变和相机坐标适配复杂性。方向混用时，不可直接共用未经变换的标定参数。
- 不混用超广角、主摄、长焦、微距自动切镜、视频截图、全景或经过未知裁剪的图片。发现模式不一致时分组匹配各自标定；无法确认时要求更正输入，不静默套用标定。
- 边移动边拍摄，使相同静态细节出现在多张照片中，同时具有位置变化。转角、门口和走廊保留两侧共同可见内容。
- 不能仅通过照片编号、时间或 GPS 确保视差充分；是否满足几何条件还需匹配、初始化和三角化验证。

## 三、具体算法与每步行为

### 1. 按拍摄文件夹导入、保留原始数据、色彩转换与质量预检

输入采用当前 Captures 的组织形式，每个拍摄文件夹作为一条完整记录：

```text
Captures/
  shot_<capture_id>/
    image.jpg
    calibration.json
  ...
```

每张图片使用同目录内的内参文件。当前样例的 JSON 标记为 schema_version=1、source=ARKit.ARFrame、units=pixels，包含 image_file、capture_id、image_width、image_height、K_rows、fx、fy、cx、cy、coordinate_space、exif_orientation、拍摄帧时间等信息。K_rows 按行存储；这些参数对应保存的图像像素，而不是手机竖屏预览。此处的 calibration.json 是随拍摄导出的逐帧参数，不是此前 OpenCV 棋盘格脚本的输出。

#### 导入与逐张内参绑定

1. 支持选择 Captures 目录，按子文件夹发现拍摄记录，忽略 .DS_Store 等非拍摄文件。每个有效文件夹应有一个 calibration.json 和其 image_file 指定的图片；图片路径必须位于该拍摄文件夹内。缺失、损坏或配对不明确时，报告具体文件夹及原因，不借用其他照片的内参。
2. 保留图片和 JSON 原始字节，分别计算哈希，保存相对目录、原始文件名、capture_id、元数据和导入批次；分配稳定 image_id，绑定图片与参数。不同文件夹内同名的 image.jpg 不互相覆盖；重复 capture_id 或内容冲突显式报告。
3. 解析并检查 JSON 版本、参数来源、单位和坐标约定；检查 K_rows 为合法 3×3 内参矩阵、数值有限、fx/fy 为正，且与单独的 fx、fy、cx、cy 字段一致。未知版本或不支持的坐标约定不得静默套用。
4. 实际解码图片，检查尺寸、格式、文件完整性和方向，并与 JSON 中的 image_width、image_height、exif_orientation 核对。尺寸或方向不一致时，先查明图像是否被外部旋转、裁剪或缩放；无法建立明确映射的记录不进入重建。
5. 每张图保留自己的 K，不因图像尺寸相同或来自同一手机就合并为统一内参。当前样例开启自动对焦，逐帧焦距已有差异。JSON 作为参数读取入口；JPEG EXIF UserComment 若含同一份参数，可用于一致性核对，冲突时报告，不静默选择。
6. distortion_coefficients=null 记录为“畸变未测量”，不能解释为零畸变。本流程不调用 OpenCV 测量内参，不执行去畸变。

#### 沿用原有图像预处理

1. 读取嵌入 ICC、HEIC 色彩描述及相关传递函数信息，按源色彩空间实际转换到 sRGB，不能仅替换色彩标签。当前样例为 JPEG；其他受支持格式仍执行对应的解码与色彩检查。
2. 对 HDR 输入采用固定、记录参数的 SDR 映射，输出 sRGB 工作副本。源色彩信息不足时记录“色彩空间未知、按 sRGB 假设”，不得标为已确认；转换不支持时报告具体原因。
3. 记录解码器是否已经应用 EXIF/容器方向，避免重复转正。当前样例声明保存的是原生传感器方向、EXIF Orientation=1；核对通过后保持该像素方向，不按竖屏预览额外旋转或裁剪。
4. 生成最长边不超过 2000 像素的彩色工作图，仅在超限时等比缩小，不放大小图，不做无记录裁剪或非等比拉伸。当前样例 JSON 声明为 1920×1440，实际解码核对一致后无需缩小。
5. 保存原图到工作图的旋转、缩放、裁剪及像素坐标约定，并生成每张图对应的工作内参 K_work。只有色彩转换且几何尺寸、方向与坐标约定不变时，K_work 保持原 K；发生缩放时按实际重采样的像素中心映射同步更新焦距和主点。发生旋转时，还需同步处理图像坐标与相机坐标轴约定，并验证投影一致性，不直接复用旧 K。接入 COLMAP 前显式核对两者像素坐标约定，不能未经验证假定一致。
6. 从 sRGB 工作图生成最长边不超过 1024 像素的灰度检测图，沿用质量检查；记录检测图缩放比例。质量检测图不替代建图用彩色工作图，检测图上的像素坐标不能直接与 K_work 混用。点云颜色仍来自彩色工作图。

| 检查 | 方法 | 行为 |
|---|---|---|
| 图片与内参配对 | 文件夹、image_file、capture_id 及 JSON 校验 | 缺失、冲突或无法确认对应关系时排除该记录并报告 |
| 尺寸、方向与内参 | 解码结果与 JSON 核对，检查变换后投影一致性 | 映射无法确认时不进入重建 |
| 损坏、格式和容量 | 解码与限额 | 确定性不合格时排除 |
| 完全重复 | 图片 SHA-256，并核对对应内参 | 图片及内参一致时保留一份、记录别名；同图参数冲突时报告 |
| 近似重复 | 64 位感知哈希 | 只提示，不自动删除 |
| 清晰度 | 灰度 Laplacian 方差 | 默认输入清晰；异常时提示可能模糊或低纹理 |
| 曝光 | 暗部、亮部像素占比 | 提示，不凭 EXIF 自动判定 |
| 纹理 | 后续 SIFT 数量与空间分布 | 结合匹配结果判断 |

预警值（2026-10-27 更新）：Laplacian 方差低于 45；灰度低于 10 或高于 245 的像素占比超过 50%；感知哈希距离不超过 4；SIFT 少于 300。它们是固定预处理条件下的产品起点，不是通用合格标准。

本步输出：原始图片及参数归档、逐张配对清单、sRGB 彩色工作图、灰度检测图、每张图的原始 K 与 K_work、坐标变换记录及质量报告。后续特征提取和几何计算使用同一工作图及其逐张内参，不增加第二步。其他章节残留的棋盘格标定、去畸变及统一内参描述尚待同步，不作为本步的前置条件或输出要求。

### 3. 上传清晰度确认与 SIFT 特征提取

上传页说明“请提供清晰照片”，不要求逐张点击确认。系统输出“未发现明显清晰度风险”或“疑似模糊/低纹理”，不声称自动证明清晰。

在去畸变后的有效区域提取 CPU SIFT，每张最多 8192 个特征，保存位置、尺度、方向和 128 维描述子。描述子规范化采用固定引擎默认配置并记录。

低分图片不自动删除，避免删除连接两个房间的关键视角。数量不足或分布集中的图片进入后续匹配判断，并在结果页显示风险。

### 4. 拍摄顺序、编号与全配对匹配

#### 顺序和编号

- 优先采用用户提供并确认的正确拍摄顺序。
- 初次导入用 DateTimeOriginal、亚秒和时区生成候选顺序；EXIF 缺失、重复或冲突时提示调整，不能用上传到达顺序冒充真实拍摄顺序。
- 页面支持拖动排序或导入顺序清单。顺序未确认时仍可建图，但不展示可信轨迹线。
- 按当前顺序分配 0001、0002 等显示编号和工作文件名；原图文件名与字节不变，内部 image_id 稳定。
- 保存编号、原文件名、image_id、时间、顺序来源、确认状态和排序版本。重排不得破坏已计算的图像关联。

#### 匹配

仍对全部图片两两匹配，不因顺序不相邻而跳过。N 张有 N(N−1)/2 对，200 张为 19,900 对，分块控制内存。

采用最近邻/次近邻距离比值测试（初始 0.8）、双向一致性和后续几何验证。时间和编号只服务排序、诊断与展示，不代替视觉对应。

### 5. 两视图几何验证

由固定版本 COLMAP 进行 F/E/H 模型估计与 RANSAC；使用已标定、去畸变的相机参数，不重复实现第二套求解器。

初始条件：4 个工作图像素误差阈值，至少 30 个几何内点，内点比例至少 20%，置信度 0.999。阈值与实际 CLI/API 对应关系需在适配层验证。

单应性占优记录为平面或低视差信号，不直接删除图片。输出内点数、比例、分布和几何类型；禁止失败后静默放宽阈值。

### 6. 图片连接图与分模型输出

节点为图片，边为通过几何验证的图片对，记录内点数、比例和几何类型。

保留孤立图、所有连通分量和最终独立模型，不强行合并。连接图连通不保证所有图片可注册，也不保证深度可靠。

对断开的房间反馈：

> 需要在门口、走廊或转角补拍同时包含两侧内容的照片。

这是补充拍摄覆盖，不是补 EXIF。报告可指出哪些编号组缺少连接，但没有共同几何约束时不能声称已经知道两个房间的真实相对位置。

### 7. 有视差的初始化与真实尺寸校准

#### 初始化

由增量 mapper 选择种子对，恢复相对旋转和平移方向，三角化，执行正深度、三角化角度、重投影误差和有效点数检查。失败则尝试其他种子对，全部失败才结束初始化。

相机移动距离未知不阻断初始化，先得到任意尺度。缺少实际平移视差则可能无法恢复稳定深度；这不能靠输入真实长度修复。低视差时要求更换拍摄位置，同时保留共同可见内容。

#### 用户输入真实尺寸

此功能在相对模型生成之后执行，界面按模型单独提供：

1. 选择两个可靠、可辨认的已重建三维点 A、B；必要时在多张已注册照片中标记同名端点，经几何验证后补充三角化。不能将任意两次屏幕点击当作三维距离。
2. 显示相对长度 d = ||A−B||，用户输入实测长度 L 和单位，统一换算成米。第一版不默认提供完整房间长宽测量。
3. 检查 d 非零、L 为有限正数，端点观测和三角化质量合格；建议选择跨度较大、定义清楚的静态端点。
4. 计算 s = L/d，对该模型的全部三维点、相机中心和外参平移统一缩放。旋转和内参不变。
5. 保存新的米制结果版本，保留原始相对模型；记录端点、长度、单位、比例、来源和测量备注。
6. 重新计算诊断、显示和导出数据。

单条长度解决整体尺度自由度，不提供足够信息修复模型的局部形变。全局等比缩放不改变重投影误差，不为此重复运行无约束 BA。若后续加入多条独立长度并希望调整形状，需要另行实现带长度残差及权重的约束优化；这不是现有标定脚本或默认 mapper 已实现的功能，不作为第一版必要项。

每个不连通模型有各自尺度，不能把模型 A 的比例直接套给模型 B。独立检查实际精度时，应使用未参与定尺度的其他实测长度。

### 8. 增量 PnP、跳过与重试

对未注册照片沿验证匹配构建 2D–3D 对应，用 PnP-RANSAC 求位姿并细化；优先处理对应多且空间分布合理的照片。

对应不足或几何验证失败时暂时跳过。随着其他相机注册和地图扩展，按固定 mapper 策略重新尝试；引擎不支持的重试行为不得在 UI 中承诺。

最终仍不能注册时：

- 有有效模型就先输出已有结果，状态为部分成功。
- 列出失败图片编号、缩略图、对应数量和可确认的失败阶段。
- 提示重拍该照片对应区域，补充与已注册区域重叠的中间视角。
- 有可信顺序时可用相邻成功照片辅助描述位置；失败照片没有可靠位姿时，不在地图中伪造精确补拍坐标。

用户补拍后创建新任务，第一版重新运行全流程，保留旧结果。

### 9. 三角化、过滤与稀疏地图报告

注册新照片后增加三维点，补充轨迹、合并一致观测并过滤异常。要求正深度、足够三角化角度、合理重投影误差和无明显轨迹冲突。

结果稀疏有两个原因：该流程只重建被匹配到的离散特征点；低质量点和观测还会被过滤。因此即使照片清晰、过滤很少，也不是稠密表面。

保留固定引擎阈值，并新增：

- 三角化角度直方图和低分位统计。每点采用有效观测对中的最大夹角作为报告定义，注明它不必等同于引擎内部所有筛选口径。
- 轨迹长度直方图、中位数和短轨迹比例；报告口径默认轨迹长度不超过 3 为短轨迹，不据此额外自动删除。
- 可获得时记录过滤点/观测数量和原因；引擎没有提供的数据标为不可用，不推算成事实。

MakerNote 对焦区域、对焦距离或对焦状态不能当作逐像素深度图。

### 10. BA 与联合质量验收

BA 优化相机位姿和三维点。基线运行固定通过验证的统一内参；诊断对照运行可按组释放焦距，比较共享内参的变化与模型稳定性。主点默认固定，已去畸变管线不再次任意拟合原始五参数畸变。

局部/全局 BA 触发、邻域、损失函数和异常观测处理采用锁定版本配置，并记录。最终 BA 和参考约束消除数值自由度，不自动产生米制尺度。

联合验收包括：

- 注册率、独立模型数量及覆盖范围。
- 中位及高分位重投影误差。
- 固定内参基线与按组细化焦距结果的差异；固定运行焦距变化为零是配置结果，不是正确性的证明。
- 标定畸变曲线、去畸变边缘效果、空间残差分布；若发现系统性边缘误差，检查标定或成像模式，不靠自由焦距掩盖问题。
- 三角化角度、轨迹长度、短轨迹比例。
- 模型是否明显折叠、重复、拉伸或出现不合理结构；自动提示与人工检查结论分别记录。
- 尺度校准后的独立实测距离误差（如有）。

统一内参比较仅在确认相同成像模式的照片组内进行。不能只挑重投影最低的结果，也不为降低误差任意剔除难样本。

### 11. 离线全局一致性优化

全配对检查再次拍摄的区域。可靠跨时段对应进入共同轨迹和全局 BA 后，可约束累计误差。

保持“离线全局一致性优化”描述，不宣称实时闭环或在线重定位。编号连续、时间相近或 GPS 相近都不证明空间关联正确；是否成功取决于视觉对应和几何验证。

### 12. 坐标、展示与导出

输出世界到相机变换 Xc = Rcw Xw + tcw，相机中心 Cw = −Rcwᵀ tcw。点云和相机使用同一显示变换。

- 相对模型明确标注“相对单位”；定尺度版本标注米及用户输入的尺度来源，不承诺测量精度。
- 不自动声称地图朝北、地面水平或具有真实重力方向。
- 确认顺序时连接同一模型内连续已注册拍摄点，标注“拍摄顺序示意”；跨失败照片的间隔断开或使用明确的虚线。不能把线段称为真实连续行走轨迹，不跨独立模型连线。
- 默认显示注册照片最多的模型，允许切换其他模型。
- 下载 PLY、相机 JSON、质量报告 JSON、原生 COLMAP 模型、图片顺序清单和尺度校准记录。
- 去畸变工作图为当前相机模型直接对应的图像；导出同时保留原图映射、原始标定与坐标变换元数据，避免把 PINHOLE 参数错误套到未经处理的原图上。

## 四、产品行为与接口

### 页面

标定档案导入与校验、照片上传和排序、检查报告、任务进度、三维结果与失败照片、尺度校准和导出。

上传完成且标定配置有效后自动检查并建图。拍摄顺序可先自动推定，不强制逐张确认；不确定时不画可信顺序线。

### 成功与失败

- 确定性排除后少于 10 张可用图时停止，这是产品限制，不是 SfM 数学最少图片数。
- 有效模型至少有 3 个注册相机和有效三维点；还需展示几何诊断，不能仅凭数量证明深度可靠。
- 主模型注册率以去除确定性无效/完全重复后的可用照片数为分母。主模型不足 80% 或存在多个独立模型时为部分成功。
- 无有效模型则失败；尺度尚未校准不算建图失败。
- 分别报告事实与可能原因。例如“注册失败”为事实，“可能重叠不足”为推断。
- 环境、依赖或引擎错误单独报告，不能归咎于照片。

### 最小接口

| 接口 | 用途 |
|---|---|
| POST /api/calibrations | 导入参数和成像配置，创建标定档案 |
| POST /api/projects | 创建项目并绑定标定组 |
| POST /api/projects/{id}/images | 上传原始照片 |
| PUT /api/projects/{id}/image-order | 保存编号顺序、来源及确认状态 |
| POST /api/projects/{id}/jobs | 启动检查和重建 |
| GET /api/jobs/{id} | 状态、阶段、检查报告 |
| POST /api/jobs/{id}/cancel | 取消任务 |
| GET /api/projects/{id}/results | 各独立模型、诊断和下载地址 |
| POST /api/projects/{id}/models/{model_id}/scale | 提交对应端点、实测长度和单位，生成尺度版本 |

尺度请求还需绑定输入模型版本，防止把旧端点套到重建后的新模型。结果含每张图特征数、连接数、注册状态，以及每模型角度、轨迹、误差和尺度状态；详细匹配数据留在后台。

### 执行与复现

仅监听本机回环地址，不上传照片到外部服务。Worker 单任务运行、其余排队，网页约每 2 秒轮询。取消终止对应进程，异常退出标记中断。重试创建新任务，不覆盖旧结果。

保存引擎与依赖版本、完整配置、随机种子、日志、图片哈希、排序版本、标定哈希、色彩转换参数、几何预处理和尺度记录。先在 Mac 验证安装和实际 CLI/API 参数，再锁定版本；不能把开发版文档中的接口直接当作本机可用接口。

## 五、实施顺序与验收

### 阶段 1：标定和算法验证

核验现有脚本和标定板，采集标定照片并检查输出；统一室内拍摄设置。跑通色彩/方向处理、去畸变、掩码、内参转换、SIFT、全配对、mapper、BA 和导出，记录实际运行时间及注册情况。此阶段不先做完整网页。

### 阶段 2：自动检查与后台

实现原图保留、标定档案、图片编号、顺序版本、色彩和几何处理、任务调度、模型诊断、失败清单与可复现导出。

### 阶段 3：网页和尺度校准

实现上传排序、风险提示、进度、分模型切换、点云与相机显示、可靠端点选择、长度输入、尺度版本和下载。

### 阶段 4：验收与异常测试

| 测试 | 验收内容 |
|---|---|
| 标定脚本 | 正确识别 9×6 内角点，检查 K 和五参数顺序、输出坐标含义 |
| 独立标定验证图 | 检查去畸变效果及边缘行为，不只看训练误差 |
| sRGB/ICC/HEIC/HDR | 原图字节不变，源色彩识别与转换记录完整，未知情况有标识 |
| 默认清晰与异常图 | 不要求逐张确认，能提示模糊/低纹理，不能误删关键连接照片 |
| EXIF 方向和缩放 | 不重复旋转，图像/特征/内参坐标一致，像素中心转换经过验证 |
| 五参数接入 | k3 未被丢失，无重复去畸变，黑边不贡献特征 |
| 统一成像模式 | 同组共享参数；不兼容输入被识别或分组 |
| 编号和顺序 | 从 0001 编号，顺序可修正，稳定 ID 和结果关联不丢失 |
| 合成相机与点 | 投影、外参方向、相机中心、重投影正确 |
| 固定室内测试集 | 主模型注册率目标达到 80%；不作为普遍保证 |
| 重投影 | 最终中位误差目标不超过 2 个工作图像素，同时报告高分位 |
| 纯旋转/低视差 | 不因匹配多或误差低就标成可靠深度 |
| 平面/重复纹理 | 输出几何诊断，不承诺所有错误关联均可自动识别 |
| 多房间断开 | 分模型输出，提示过渡区域补拍，不虚构相对布局 |
| PnP 对应不足 | 暂跳、重试、保留部分模型及失败图清单 |
| 稀疏点诊断 | 角度和轨迹统计定义明确，缺失引擎指标不伪造 |
| 真实尺寸 | X、相机中心、t 同步缩放，R/K 不变，重投影不变，模型分别定尺度 |
| 错误长度或端点 | 零距离、负值、单位错误、版本冲突和不可靠端点可识别 |
| 取消/中断/重试 | 状态与进程生命周期一致，不覆盖历史结果 |
| 导出 | 外部工具可读，原图与工作图相机关系明确 |

有真实轨迹时，无尺度模型采用 Sim(3) 对齐评价；评价定尺度结果应保留尺度误差，不能再自由拟合尺度把误差消除。无测量真值时，不输出厘米级精度承诺。

## 六、交付范围与修订摘要

交付目标：可在当前 Mac 启动的本机网页原型、标定接入、拍摄指南、算法配置、测试记录、分模型结果及可选米制尺度版本。

相对原计划的主要变化：

1. 原图不变，工作图先做实际 sRGB 转换，再灰度化和质量检查；默认清晰但保留异常提示。
2. 用用户现有棋盘格脚本建立标定档案，固定拍摄设置；默认五参数去畸变后用共享 PINHOLE 接入。
3. 增加 0001 式编号、可修正顺序及可信度记录；保留全配对。
4. 明确断开房间的过渡视角补拍和 PnP 跳过重试行为。
5. 保留稀疏地图，并增加三角化角度和短轨迹报告。
6. 新增用户实测长度定尺度；与需要额外观测和实现的形状约束优化区分。
7. 扩大验收指标，保持离线全局一致性优化的范围。
