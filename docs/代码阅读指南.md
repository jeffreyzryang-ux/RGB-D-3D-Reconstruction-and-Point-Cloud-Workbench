# 代码阅读指南

先读 backend/app.py 的 process，再按调用顺序阅读三个计算脚本。

## 主流程

1. frontend 上传数据；backend/app.py 的 upload_file 或 upload_zip 接收文件。
2. complete 把任务加入队列，worker 取出任务并调用 process。
3. validate_source 检查图像、内参、深度和置信度格式。
4. parse_capture_depth.py 解析深度并生成统计、预览。
5. reconstruct_captures.py 提取特征、匹配照片、求解相机位姿和稀疏点云。
6. fuse_lidar_depth.py 使用实测深度恢复尺度，将点变换到同一世界坐标系，检查跨视角一致性并按体素融合。
7. audit_capture_result.py 检查结果；后端返回状态与文件地址供前端展示。

## 常见变量

- K / k：相机内参矩阵；像素坐标反投影需要它的逆矩阵。
- R / t：世界坐标到相机坐标的旋转与平移。
- d / depth：相机坐标的 Z 深度，单位米，不是到相机中心的径向距离。
- c / conf：在深度融合中表示置信度；0 低、1 中、2 高。在数据库函数中 c 表示连接。
- xyz / rgb：三维坐标和对应颜色，每行代表一个点。
- support / conflict：其他视角提供一致深度或几何冲突的次数。
- scale：将 SfM 任意尺度转换为米的倍率。

## 文件范围

工作台主要调用上述四个算法脚本；dense_cpu.py 的 ply 函数用于写点云。其他 scripts 文件包含早期标定与诊断实验，不是每次网页建模都会运行。历史报告生成脚本已移至 report_generators/，生成文件仍存放于 reports/；使用方式见 report_generators/README.md。

## 保持格式

在项目终端执行 `.venv/bin/python -m black backend scripts report_generators`。
修改后执行 `.venv/bin/python -m unittest discover -s tests -v`。
Captures4 数据测试需要提供测试素材，详见工作台使用说明。
