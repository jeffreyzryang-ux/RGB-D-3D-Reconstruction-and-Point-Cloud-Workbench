# Captures4 RGB-D 建模系统：前后端实施方案

日期：2026-10-28。本文是设计与实施计划，不代表前后端已实现。第一版在当前 Mac 本机运行，浏览器访问回环地址；照片、深度与模型在本机保存。

## 1. 目标与输入

用户选择一个拍摄目录或 ZIP，前端上传完整批次；服务端校验完成后自动排队建模，前端显示进度并加载可交互彩色点云。默认接受中/高置信度（1、2），低置信度（0）排除。

仅上传 JPEG 不足以复现 Captures4 的深度建模。每组需包含 image.jpg、calibration.json、depth.json、depth.f32、confidence.u8；批次可包含 order.json。支持文件夹选择和 ZIP 上传，保留相对路径避免同名 image.jpg 冲突。未提供顺序时只生成候选顺序，不冒充可信轨迹。

上传结束以显式 complete 请求提交批次，不能每收到一张图片就启动模型。有效批次自动建模，确定性错误先展示具体文件及原因。小于10张仅在用户显式开启小批量诊断模式时接受3–9张，默认10–200张。建议初期总容量上限2GB，按文件类型分别校验长度与限额。

## 2. 架构

React + TypeScript + Vite 前端；Three.js 点云查看器。
FastAPI 服务提供上传、状态、结果和下载接口；SQLite 保存项目、批次、任务、模型版本；文件目录保存原图、深度、工作图、日志和模型。
独立 Python Worker 单任务运行，其余排队；API 请求不直接执行重建。任务进程可终止，重启后扫描并标记中断，重试新建版本。服务端任务状态为唯一事实来源。
第一版本机同源部署：构建后的前端由后端提供，绑定127.0.0.1。当前 PyCOLMAP/OpenCV 计算依赖不部署到浏览器或边缘Worker；如后续远程部署，需独立计算服务器、认证和存储访问控制。

## 3. 后端阶段

1. 上传落盘与校验：文件名与路径安全、ZIP路径穿越/软链接/解压后体积限制、批次原子提交、SHA-256、重复检测；错误类型区分数据问题和环境问题。
2. 深度解析：复用 parse_capture_depth.py 的已验证规则；版本1/2分别路由，RGB-D路径要求schema2深度字段、float32小端、精确字节数、置信度范围、尺寸、EXIF一致性、时间戳和K映射。每阶段输出机器可读产物，不解析控制台文本作为成功依据。
3. 图像预处理：颜色/方向/工作内参、清晰度预警45；默认不因清晰度提示删图。生成缩略图、统一色标深度预览及置信度预览。
4. SfM：逐张内参固定，CPU SIFT、全配对几何验证、增量重建和BA。输出独立模型和未注册图，不强行拼接无约束模型。保留引擎自动放宽初始化的日志和状态标记。
5. 米制尺度：对每个独立模型以稀疏观测与中高置信度LiDAR深度建立尺度比，避开深度边缘，稳健估计并检查样本数、离散度和逐帧差异。不一致时停止该模型融合，不输出貌似正常的错位模型。
6. RGB-D反投影和融合：接受confidence=1/2；按K_depth和Z反投影，依据定尺度相机位姿变换到统一坐标。跨视角支持/遮挡/冲突检查，默认5mm体素合并；不把5mm合并间距宣称为测量精度。
7. 导出与复核：主点云、额外多视角支持点云、米制相机JSON、统计报告、原生SfM模型、参数和源文件哈希；保存版本、不覆盖历史结果。

现有脚本重构为库函数和CLI薄入口：reconstruct_captures.py、parse_capture_depth.py、fuse_lidar_depth.py、audit_capture_result.py。移除固定模型0、固定图片名与默认单模型的隐含假设；将硬编码参数归入带版本配置。先补输入和坐标验证，再接API。

## 4. 任务与API

状态：uploading → validating → queued → preprocessing → sfm → scale_estimation → depth_fusion → exporting → succeeded / partial / failed。任意运行阶段可进入cancelling → cancelled；进程异常进入interrupted。

|接口|作用|
|---|---|
|POST /api/projects|建立项目|
|POST /api/projects/{id}/uploads|建立上传批次|
|PUT /api/uploads/{id}/files/{file_id}|上传文件，原始相对路径作为元数据校验，不直接用作目标路径|
|POST /api/uploads/{id}/complete|原子提交；校验后自动创建任务，幂等避免重复建图|
|GET /api/jobs/{id}|阶段、计数、耗时、预警、日志摘要|
|POST /api/jobs/{id}/cancel|取消任务及子进程|
|POST /api/jobs/{id}/retry|以新版本重跑|
|GET /api/projects/{id}/results|独立模型和结果版本|
|GET /api/models/{id}/manifest|点云加载地址、单位、包围盒、层级、诊断|
|GET /api/artifacts/{id}|受控读取/下载，不接受任意系统路径|
|POST /api/models/{id}/scale|可选：基于外部实测距离创建新版本|

第一版每2秒轮询；进度使用真实阶段和已处理计数，没有计数的阶段显示不确定进度，不伪造百分比。阶段时间实测记录，不用当前12张样本11秒的速度承诺所有任务。

## 5. 前端页面与视觉样式

整体为中文桌面工作台。浅色导航及数据面板、深色三维画布；低饱和蓝作主要操作，绿色表示完成、橙色表示风险、红色表示失败，配合文字而非仅靠颜色。

颜色建议：页面#F5F7FA，面板#FFFFFF，正文#182230，次要文字#667085，边线#E4E7EC；画布#151B24；主操作#2563EB。字体系统中文无衬线，正文14px、页面标题22px；面板圆角10px，24px页面间距。不使用装饰性渐变或重阴影。

### 页面A：上传与检查

左侧项目导航，中部目录/ZIP上传区，右侧本次配置（默认中+高、5mm融合、清晰度45）。文件清单按拍摄组展示5项配对状态；上传后显示检查进度。提示“请上传完整拍摄文件夹，单独照片不包含深度”。校验通过自动建模；失败行可展开具体原因。选择文件、提交、任务创建均防重复操作。

### 页面B：建模进度

阶段列表显示校验、相机定位、深度融合、导出；中央显示当前阶段、实测耗时、已处理张数。右侧显示预警及可展开日志。支持取消，页面刷新可恢复状态。注册照片不足只显示已确认的失败阶段，不擅自声称因模糊导致。

### 页面C：模型工作台

顶部：项目名称、版本、状态、单位、导出。
左栏240px：照片缩略图、注册状态、RGB/深度/置信度切换。
中央自适应深色画布：点云旋转、平移、缩放、适应全部、相机位置开关；明确标注米。仅相机坐标定义的视角不命名为真实“俯视/朝北”。
右栏300px：注册率、点数、置信度接受规则、尺度来源、重投影诊断、尺度一致性、预警；主点云/多视角支持版本切换。
底部：当前任务状态和鼠标操作提示。

初始设计采用Captures4真实结果：12/12、209205点、LiDAR米制；展示为“已有样例结果”，不能冒充新上传任务输出。

窄屏折叠左右栏为抽屉，画布优先。原生按钮、键盘焦点、表格语义、文字状态支持无障碍。点云区域提供摘要和下载作为图形之外的替代访问方式。

## 6. 点云传输与测量

12张当前20.9万点可优先用二进制PLY直接加载。后端同时生成低分辨率预览点集，先显示再切完整结果；更大模型启用分块/LOD、可配置点数预算，避免超大JSON一次性传输。浏览器GPU内存和手机性能需实测。
测量只允许选真实三维点，显示端点和距离，不把任意屏幕点击变成测量点。模型自带LiDAR米制，不默认重新定尺度；外部实尺校准单独创建版本。用户输入与模型估测来源必须区分。第一版不承诺自动物体识别、自动屏幕边界或测量精度。

## 7. 实施顺序与验收

阶段1：整理输入契约、参数配置和可重入算法模块；以Captures4固定测试集验证中高置信度选择、投影、尺度不变性、数据哈希及多模型隔离。
阶段2：完成上传、SQLite状态、Worker、取消/中断/重试、结果导出；模拟缺文件、错字节数、错时间戳、非法路径及深度尺度不一致。
阶段3：实现上传/进度/模型三页，打通自动调用；使用真实结果检查PLY载入、颜色、单位、相机位置和点选距离。
阶段4：端到端验收和本机启动脚本，记录真实耗时与内存。验证从空项目上传Captures4到模型可交互；低置信度不进入输出；刷新不丢任务；取消不遗留子进程；重试不覆盖结果；导出PLY可由独立工具读取。

交付：frontend/、backend/、算法模块、启动与依赖说明、API文档、测试记录、样例配置。本轮只输出计划与样式稿，不启动网站或发布照片。
